# LEGAL_REASONING.md

本文件定义复杂纠纷、合同争议、仲裁/诉讼准备中的争点挖掘、推断逻辑和法条适用边界规则。它用于避免报告只停留在“列事实、列结论”，而缺少争点之间的依赖关系、证明路径和法律规则的适用条件。

## 1. 触发条件

出现以下任一情况，必须使用本规范：

- 用户描述的是争议、纠纷、索赔、返还、补偿、解除、违约、侵权、仲裁、诉讼或行政投诉。
- 对方已有主张、抗辩、反请求、反仲裁、答辩或和解报价。
- 报告需要评估胜率、风险、金额区间、谈判策略或裁判路径。
- 需要引用法律条文、司法解释、案例、行政规则或地方裁判口径。

## 2. 争点挖掘顺序

复杂纠纷不得直接从用户问题跳到结论。必须先建立争点树：

```text
案件一句话地图
→ 母命题
→ 条件命题
→ 反制命题
→ 金额命题
→ 程序命题
→ 证据命题
→ 策略命题
```

### 母命题

决定全案方向的核心争点。通常回答：

- 真实法律关系是什么。
- 款项、行为、条款或责任的性质是什么。
- 哪个事实一旦成立，会带动其他请求或抗辩。

### 条件命题

母命题成立后才有意义的争点。比如工资基数成立后，才进一步影响加班费、补偿金、年假工资或欠薪金额。

### 反制命题

专门用于回应对方请求、抗辩、返还、抵销、时效、主体不适格或证据攻击的争点。

### 金额命题

涉及金额计算、期间、基数、倍率、扣减、抵销、上限、损失扩大和可得利益的争点。

### 程序命题

涉及管辖、时效、仲裁前置、举证期限、调查令、证据保全、行政投诉和执行可行性的争点。

### 证据命题

涉及证据真实性、合法性、关联性、证明力、原件、形成时间、上下文、完整性和对方掌握材料的争点。

## 3. 每个争点必须回答的问题

每个核心争点至少写清：

| 字段 | 要求 |
|---|---|
| 争点名称 | 用一句话描述要裁判或谈判的问题 |
| 争点类型 | 事实 / 法律 / 证据 / 因果 / 金额 / 程序 / 策略 |
| 用户命题 | 用户希望证明什么 |
| 对方命题 | 对方最可能如何否认、解释或反击 |
| 证明责任 | 谁先证明，谁对抗辩事实证明 |
| 现有证据 | 哪些证据直接或间接支持 |
| 关键缺口 | 缺什么会导致败诉、降额或谈判弱化 |
| 推断链条 | 从事实到法律评价的中间步骤 |
| 法律依据 | 已核验来源或待核验规则 |
| 适用边界 | 该规则何时适用、何时不适用 |
| 裁判路径 | 法官/仲裁员可能按什么顺序审理 |
| 策略意义 | 对金额、谈判、程序或文书的影响 |

## 4. 法条适用边界

引用任何法律规则时，不能只写条文名称或结论。必须说明适用边界：

| 边界 | 检查问题 |
|---|---|
| 法域边界 | 该规则适用于哪个国家、地区、法院层级或行政领域 |
| 时间边界 | 规则是否现行有效，是否适用于案发时间 |
| 主体边界 | 规则适用于劳动者、消费者、经营者、公司、平台、行政机关还是其他主体 |
| 行为边界 | 规则约束的是付款、解除、通知、违约、侵权、证据、程序还是执行 |
| 要件边界 | 规则成立需要哪些事实要件 |
| 例外边界 | 有无除外情形、抗辩、免责、上限或裁量空间 |
| 证明边界 | 谁承担证明责任，证明到什么程度 |
| 后果边界 | 支持的是确认、履行、赔偿、返还、补缴、处罚、解除还是程序后果 |
| 类推边界 | 案例或裁判观点与本案事实有哪些相似和差异 |
| 风险边界 | 哪些地方不能过度引用，哪些结论必须标记待核验 |

如果无法完成边界分析，应在 `sources.md` 和报告中标记为“待核验规则”，不能写成确定法律结论。

## 5. 推断逻辑规则

争点分析必须显式展示推断链：

```text
证据 A / 事实 A
→ 可推断事实 B
→ 对应法律要件 C
→ 支持或削弱争点 D
→ 影响请求/抗辩/金额/策略 E
```

禁止：

- 只写“因此胜率较高”而不展示中间推断。
- 只列法条不说明要件。
- 只列证据不说明证明对象。
- 把单一证据直接推出最终胜败。
- 忽略对方的替代解释。

## 6. 争点关系输出

复杂报告必须有“争点关系”章节。可用三种形式之一：

1. 文字链条：`母命题 → 条件命题 → 金额/程序后果`。
2. 关系表：列明每个争点依赖哪些前置争点。
3. 流程图：如果能被正确渲染为图片或图形，可使用流程图；不能渲染时改为关系表。

## 7. 文件落点

执行本规范时，应更新：

- `case.md`：母命题、核心争点、程序状态。
- `analysis.md`：争点树、推断链、法条适用边界。
- `evidence.md`：每个争点的证据支撑和缺口。
- `sources.md`：规则来源、核验状态和引用风险。
- `skill_outputs.md`：记录本轮争点挖掘和边界分析进入最终报告的章节。
