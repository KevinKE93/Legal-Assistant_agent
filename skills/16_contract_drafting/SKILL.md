# Skill：合同起草

## 目标

1. 将交易背景和用户目标转化为合同结构。
2. 明确权利义务、付款、交付、验收、违约、解除和争议解决。
3. 给出强保护版、中性版或可谈判版条款。
4. 生成面向用户的合同草案或条款清单。

## 输入

- 合同类型和交易背景。
- 当事人角色。
- 标的、金额、期限和履约方式。
- 用户必须保护的利益和不可接受风险。
- 对方可能坚持的条件。
- 适用法域、管辖或争议解决偏好。

## 工作流

### 1. 起草前提

先记录：

| 项目 | 内容 | 状态 |
|---|---|---|
| 合同类型 |  | confirmed / assumed |
| 用户角色 |  |  |
| 交易目标 |  |  |
| 关键金额/期限 |  |  |
| 不可接受风险 |  |  |
| 待补信息 |  |  |

信息不足时，不停止起草；用 `[待确认：...]` 标记占位。

### 2. 条款结构

常用结构：

1. 当事人和定义。
2. 合同标的。
3. 交付、验收或服务范围。
4. 价款、付款、发票和税费。
5. 双方权利义务。
6. 陈述、保证和合规承诺。
7. 知识产权、保密、数据和隐私。
8. 期限、续约、暂停和解除。
9. 违约责任、赔偿、责任限制。
10. 不可抗力和通知。
11. 适用法律和争议解决。
12. 附件、优先级和签署。

### 3. 风险分配

对关键风险给出条款选择：

| 风险 | 用户保护版 | 中性版 | 对方友好版 | 推荐 |
|---|---|---|---|---|

### 4. 草案写法

- 使用清晰、可执行、可证明的条款。
- 避免只写原则，不写期限、标准、后果。
- 对金额、日期、主体和附件用占位符时标明待确认。
- 对高风险事项附加谈判说明，不混入合同正文。

## 输出文件

- `term_sheet.md`：交易要点和条款结构。
- `contract_draft.md`：合同草案正文。
- `advice.md`：谈判、签署和待补信息。
- 本地化最终文件：`合同草案-<合同主题>.md` 或 `Contract Draft - <topic>.md`。

## 输出格式

```markdown
## 起草前提

## 条款结构

## 合同草案

[正文]

## 可谈判条款
| 条款 | 用户保护版 | 中性版 | 对方可能要求 | 建议 |
|---|---|---|---|---|

## 待确认信息
1.

## 签署前核验清单
1.
```

## 质量检查

- 不编造当事人身份、授权、金额、日期或附件。
- 每个核心义务都应有时间、标准、证据和违约后果。
- 草案正文和谈判说明分开。
- 对重大不确定事项使用占位符并列入待确认清单。
