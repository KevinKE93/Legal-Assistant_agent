# Skill：最终汇总与交付

## 目标

1. 逐项读取事项文件夹内的工作文件，而不是只读 `analysis.md`。
2. 从专业、审慎、中立的角度重组结论、依据、风险和下一步。
3. 在对话界面展示用户可直接理解的最终摘要。
4. 输出本地化命名的 `.md` 总结文件和同名 `.pdf`。

## 输入

- 事项文件夹路径，必须是 `work/<date>_<本地化事项名>/`。
- 用户主语言和目标读者。
- 已存在的工作文件。
- 是否存在 PDF 导出工具或宿主环境 PDF 能力。

## 必读文件

按存在情况逐项读取：

```text
plan.md
case.md
timeline.md
evidence.md
sources.md
analysis.md
advice.md
drafts.md
hearing.md
negotiation.md
contract.md
clause_review.md
term_sheet.md
contract_draft.md
```

缺失文件不阻塞汇总，但必须在总结中说明“未见/待补”的关键材料。

## i18n 与命名

- 中文输入：事项目录和总结文件必须使用中文主题，例如 `work/2026-05-10_劳动争议_拆分发薪加班费/`。
- 中文总结：`<法律问题主题>总结.md` 和 `<法律问题主题>总结.pdf`。
- 英文总结：`<Topic> Summary.md` 和 `<Topic> Summary.pdf`。
- 保留法条名、合同原文、证据备注和用户原始短语，不强行翻译。
- 禁止使用 `work/cases/`。

## 汇总工作流

### 1. 读取与校验

建立文件清单：

| 文件 | 是否存在 | 用途 | 是否影响结论 |
|---|---|---|---|

### 2. 交叉核对

检查：

- `case.md` 的关键事实是否被 `evidence.md` 支撑。
- `analysis.md` 的结论是否被 `sources.md` 或待核验规则支撑。
- `advice.md` 的行动建议是否匹配证据强度。
- 合同类事项中 `clause_review.md` 或 `contract_draft.md` 是否与用户目标一致。
- 是否存在前后矛盾、金额矛盾、程序矛盾或语言/命名不符合 i18n 的问题。

### 3. 重组最终结论

不要复制工作底稿。按用户阅读顺序重写：

1. 目的与范围。
2. 核心结论摘要。
3. 关键事实/合同背景。
4. 争议焦点/条款风险/研究问题。
5. 分析理由。
6. 风险和不确定性。
7. 下一步行动。
8. 来源和引用风险。
9. 待补材料。

### 4. 输出 Markdown

写入：

```text
<事项文件夹>/<本地化主题>总结.md
```

合同审查、合同起草和法律研究可使用更具体名称：

```text
<合同主题>合同审查总结.md
<合同主题>合同草案.md
<主题>法律研究总结.md
```

### 5. 输出 PDF

将同一内容导出为同名 PDF：

```text
<事项文件夹>/<本地化主题>总结.pdf
```

优先使用宿主环境提供的 PDF/文档导出能力；其次使用可用的 Markdown 转 PDF 工具，例如 `pandoc <summary.md> -o <summary.pdf>`；再其次使用浏览器打开 Markdown/HTML 后打印为 PDF。不得假称已生成 PDF。若当前环境无法导出 PDF：

- 在 `plan.md` 标记 `PDF status: blocked`。
- 写明阻塞原因。
- 在对话中说明 Markdown 已生成、PDF 待转换。

### 6. 对话界面展示

最终回复必须用用户语言展示：

```markdown
## 最终总结
- 核心结论：
- 最大风险：
- 下一步三项动作：
- 已生成 Markdown：
- 已生成 PDF：
```

## 质量检查

- 不遗漏 `plan.md` 和 `case.md`。
- 不把待证明事实写成已证明事实。
- 不把工作底稿直接复制为总结。
- 中文输入不得输出英文目录名或英文总结文件名。
- PDF 路径必须真实存在；否则明确说明未生成及原因。
