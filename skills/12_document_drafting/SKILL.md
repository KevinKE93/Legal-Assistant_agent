# Skill：法律文书与沟通文本起草

## 适用场景

用户需要起草或优化：

- 事实确认消息。
- 协商函。
- 催告函。
- 投诉材料。
- 调解申请。
- 起诉状框架。
- 答辩状框架。
- 证据目录。
- 庭审陈述提纲。

## 目标

1. 将事实、证据、请求转化为清晰文本。
2. 降低情绪化和法律结论过度的问题。
3. 保留必要的法律立场和证据指向。
4. 避免不当承认、威胁、诽谤或泄露隐私。

## 输入

- 文书用途。
- 接收对象。
- 用户身份。
- 事实摘要。
- 证据清单。
- 诉求。
- 希望语气。
- 是否用于正式程序。

## 工作流

### 1. 明确文书功能

不同文书有不同目标：

| 文书 | 目标 |
|---|---|
| 事实确认消息 | 锁定对方陈述和关键事实 |
| 协商函 | 推动解决，保留证据 |
| 催告函 | 明确期限和后果 |
| 投诉材料 | 向平台/行政机关说明事实和请求 |
| 起诉状 | 明确当事人、请求、事实理由、证据 |
| 答辩状 | 反驳请求、事实和法律依据 |
| 证据目录 | 说明证据名称、来源、证明对象 |

### 2. 文书结构

通用结构：

```text
标题
收件对象
身份与关系
事实时间线
证据对应
请求事项
期限或下一步
保留权利
落款
```

### 3. 降噪处理

将以下表达改写：

- 情绪攻击 → 事实描述。
- 道德评价 → 证据支持的行为描述。
- 绝对结论 → 保留性法律表述。
- 威胁语气 → 合法权利保留。

### 4. 风险审查

审查是否存在：

- 自认不利事实。
- 超出证据的指控。
- 泄露隐私。
- 威胁、胁迫或诽谤。
- 错误法律路径。
- 金额计算不清。

## 输出格式

```markdown
## 文书用途与风险提示

## 草稿

[正文]

## 逐项说明
| 段落 | 目的 | 证据依据 | 风险 |
|---|---|---|---|

## 可替代表达
| 强硬版 | 中性版 | 温和版 |
|---|---|---|

## 使用前核验清单
1. 当事人信息是否准确但不过度暴露隐私。
2. 日期、金额、证据编号是否准确。
3. 是否保留原始证据。
4. 是否需要律师审阅。
```

## 质量检查

- 文书请求清楚。
- 事实与证据对应。
- 避免违法威胁和诽谤。
- 不编造法条和案例。
